## 一、项目概况

「林元元」中医生活日化品牌的自营电商微信小程序，采用**品牌直营 + 单级分销**模式：

- **C 端（消费者）**：浏览商品、加购、下单、微信支付、查物流、退款售后
- **B 端（店主/运营/财务）**：网页版管理后台，负责订单发货、库存、商品、退款审批、分销员管理、提现审批
- **C 端（代理/分销员）**：小程序内分销中心，专属二维码推广、佣金查看、提现申请

佣金模式：单级分销，固定可调比例（存于数据库 `admin_config`，当前默认 **33%**），订单确认收货后佣金解冻可提现。

## 四、核心业务与资金流

### 4.1 购物主流程

下单锁定库存（reservedStock）→ 微信支付 → payNotify 回调核验（openid + 金额）→ 正式扣库存、记现金流水、佣金入 frozen → 发货 → 确认收货（或 7 天自动）→ 佣金 frozen → settled。

30 分钟未支付由 maintenance 释放库存。支付对账有自愈逻辑（卡单自动修复）。

### 4.2 退款

买家申请 → B 端审批同意即自动执行（cloudPay 服务商模式 + AppSecret 自触发链路）→ 微信 SUCCESS 后事务同步。失败单据转「待人工核查」，B 端有「重试退款」按钮（微信按 outRefundNo 幂等，不会重复退）。

⚠️ **新商户常见坑**：收款次日结算到银行卡，商户基本账户没钱会拒退。需在商户平台充值后重试。

### 4.3 提现 ⚠️ 当前为半自动（重点交接项）

**设计目标（代码已就绪）**：代理小程序申请 → B 端审批 → 自动调微信商家转账 API（升级版 transfer-bills，1005 佣金场景）→ 代理微信确认收款 → 完成。防重复转账、单笔 ≥0.3 元均已实现。

**当前实际状态：自动打款被套餐卡住，暂走人工模式**：

1. 代理在小程序申请提现 → B 端审批通过（单据停在 pending_pay「待打款」）
2. 店主登录 pay.weixin.qq.com → 产品中心 → 商家转账 → **手动发起转账**（扫脸确认）
3. 回 B 端点「确认已打款」

**卡点根因（2026-09-14 定性）**：
- 微信要求调转账 API 必须配固定出口 IP 白名单
- 云开发环境当前为**免费体验版**套餐，官方明确固定公网出口 IP 仅「标准版及以上」支持（¥179.10/月起）
- 已实测验证：升级套餐后用 CLI 一条命令即可开启 EIP（路径已跑通），无需网页操作

**升级套餐后恢复自动转账的步骤**（未来操作）：
1. tcb.cloud.tencent.com → 套餐用量 → 升级标准版

## 六、重要技术坑档案（踩过的坑，接手必读）

按严重程度排列：

1. **云函数事务禁并发**：`db.runTransaction` 内严禁 `Promise.all`——事务会话不支持并发，报 TransactionBusy。提现功能曾因此上线即失败。事务内一律逐个 await。
2. **CLI 部署重置超时**：`cli cloud functions deploy` 会把函数超时重置为默认 3 秒（两次真机事故）。每次 CLI 部署后必须立即补设超时（标准值见 cloudbaserc.json）。**优先用 MCP updateFunctionCode 部署**（不重置配置，但有 1-3 分钟传播延迟）。
3. **wx-server-sdk 嵌套对象坑**：update 嵌套对象会被展平成点路径，null 字段上建子字段直接报错。整体替换用 `_.set()`；文档不要写 `字段: null` 占位。
4. **payNotify 回调身份口径**：云开发服务商模式回调，`event.openid` 是平台侧标识，**`event.subOpenid` 才是小程序用户**。写错则真实支付回调永远失败。
5. **退款必须带小程序票据**：B 端网页/直调没有票据（-501001）。解法：AppSecret 换 stable_token → `api.weixin.qq.com/tcb/invokecloudfunction` 自触发（SOURCE=wx_http 上下文 cloudPay 可用）。AppSecret 已配在 admin 云函数环境变量 `MINIPROGRAM_APPSECRET`。
6. **B 端静态资源缓存**：每次改 admin-web 必须升 index.html 版本号，否则浏览器缓存旧 JS 导致白屏。
7. **支付 mock 双开关**：模拟支付必须同时开数据库 `pay_config.useMockPay=true` + pay 函数环境变量 `ALLOW_MOCK_PAY=true`，任一缺失不生效。上线时两者必须都为 false。
8. **部署传播延迟**：云函数部署后立即调用可能命中旧热实例，等 1-2 分钟再验证。
